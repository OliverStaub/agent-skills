# D2 Reference (d2lang.com)

Verified reference for writing D2 diagrams of software systems and rendering them with the
`d2` CLI. Sourced from the official tour docs (https://d2lang.com/tour/*) and the d2 source
(`d2ast/keywords.go`, `d2target`, `d2cli`).

## 1. CLI quick reference

```sh
d2 in.d2                      # -> in.svg (SVG is the default output)
d2 in.d2 out.svg
d2 in.d2 out.png              # also .pdf .pptx .gif .txt (ASCII art)
d2 --layout=elk in.d2 out.svg # -l dagre|elk|tala   (env: D2_LAYOUT)
d2 --theme=0 in.d2            # -t <id>             (env: D2_THEME)
d2 --dark-theme=200 in.d2     # theme used when the viewer's browser is in dark mode (SVG only)
d2 --sketch in.d2             # -s  hand-drawn look
d2 --pad=20 in.d2             # pixels of padding around the diagram (default 100)
d2 --scale=1 in.d2            # default -1: SVG fits to screen; 1 = natural size; 0.5 = half
d2 --center in.d2             # -c  center the SVG in its viewbox
d2 --bundle=false in.d2       # -b  bundle assets into the SVG (default true)
d2 --watch in.d2              # -w  live-reload server (opens a browser)
d2 --timeout=300 in.d2        # seconds; raise for large diagrams (default 120)
d2 in.d2 --stdout-format png - > out.png   # '-' = stdin/stdout
d2 --layout=elk --elk-algorithm=layered|force|stress|mrtree|radial in.d2

d2 fmt file.d2 ...            # autoformat in place (--check only reports)
d2 validate file.d2           # compile without rendering; non-zero exit on errors
d2 layout                     # list layout engines; `d2 layout elk` shows that engine's flags
d2 themes                     # list theme IDs (0 Neutral Default, 1 Neutral Grey, 4 Cool Classics,
                              #   8 Colorblind Clear, 200 Dark Mauve, 300 Terminal, 303 C4, ...)
```

- Every flag is also an env var (`D2_LAYOUT`, `D2_THEME`, `D2_PAD`, `D2_SKETCH`, ...) or a
  `vars.d2-config` entry in the file (section 5). Flags and env vars win over `d2-config`.
- **PNG/PDF/PPTX/GIF and the headless browser.** Before v0.9.0 the raster exporters use
  Playwright to drive headless Chromium, downloading a Chromium build on first PNG export.
  Offline or in a sandbox without a usable Chromium the export fails (`failed to launch
  Chromium` / Playwright install errors). Workaround: emit SVG and rasterize with
  `rsvg-convert`, `cairosvg`, `inkscape` or `resvg`. From v0.9.0 the raster formats use a
  built-in Go renderer and need no browser. Check `d2 --version`.
- **TALA** was a separate proprietary plugin with a license key; since v0.9.0 it is open
  source and bundled. If `d2 layout` does not list `tala`, that build cannot use it.

## 2. Core syntax

```d2
# Shapes: a bare key declares a rectangle labeled with the key. Keys are case-insensitive.
api
pg: PostgreSQL                     # key: label
pg.shape: cylinder                 # dotted attribute
cache: Redis { shape: cylinder }   # attributes in a map
a; b; c                            # several declarations on one line

# Connections: -> <- <-> --   (undeclared endpoints are auto-created)
api -> pg: reads/writes            # label after the colon
api <-> cache
job -- queue                       # undirected
lb -> api -> pg: hop               # chaining; the label applies to every hop
api -> pg                          # repeating a connection ADDS an edge, it does not override
(api -> pg)[0].style.stroke: red   # reference an existing connection by index

# Containers
aws: AWS {                         # shorthand label
  vpc: {
    label: Production VPC          # or the label keyword
    api
    db: { shape: cylinder }
    api -> db
  }
}
users -> aws.vpc.api               # dotted absolute paths work anywhere
other: {
  _.users -> _.aws                 # _ = parent scope, to reach outside the container
}

direction: right                   # up | down (default) | left | right; global (per-container: TALA only)

# Comments: # to end of line; a """ ... """ block is a block comment
"key: with colon" -> 'weird {} key'  # quote strings containing : ; { } | # or leading/trailing spaces
msg: "it's \"quoted\""               # backslash escapes inside double quotes
x.style.fill: "#f4a261"              # hex colors MUST be quoted, otherwise # starts a comment
multi: first line\nsecond line       # \n = line break in a label

# Block strings: |md (Markdown), |<lang> (code: go js ts py rb sh sql json yaml ...), |latex
# If the body itself contains |, open/close with || or |` ... `| instead.
notes: |md
  # Heading
  - bullet, **bold**, `code`
|
```

- A `|md` value is a standalone Markdown text shape; add `shape: rectangle` explicitly if
  it should have a box. `shape: text` gives plain, non-Markdown text.
- Other per-object keywords: `link: <url>`, `tooltip: <text>`, `icon: <url|path>`,
  `width`/`height` (px), `near` (section 11), `constraint` (sql_table only).

## 3. Shape catalog

Set with `shape: <value>`; default `rectangle`.

| Purpose | `shape:` values |
| --- | --- |
| Boxes | `rectangle` (default), `square`, `page`, `parallelogram`, `document`, `package`, `step`, `callout` |
| Data / storage | `cylinder` (database), `queue`, `stored_data` |
| Flow / decision | `diamond`, `oval`, `circle`, `hexagon` |
| Actors / infra | `person`, `c4-person`, `cloud` |
| Text | `text` (plain), `code` |
| Special | `sql_table`, `class`, `sequence_diagram`, `image` (needs `icon:`) |

`circle` and `square` keep a 1:1 aspect ratio. Standalone image: `shape: image` +
`icon: <url>`. Icon inside a normal box: just set `icon:` (free catalog at
https://icons.d2lang.com, e.g. `icon: https://icons.d2lang.com/aws%2FStorage%2FAWS-Backup.svg`).

## 4. Style keywords

All live under `style` (`x.style.fill: red` or `x: { style: { fill: red } }`); they apply to
shapes and connections unless noted.

| Keyword | Values | Notes |
| --- | --- | --- |
| `opacity` | 0-1 | |
| `fill` | CSS color name, `"#hex"`, `transparent`, `"linear-gradient(...)"` | shapes only; on `sql_table`/`class` colors the header |
| `fill-pattern` | `dots`, `lines`, `grain`, `none` | shapes only |
| `stroke` | color | on `sql_table`/`class` it fills the body |
| `stroke-width` | 1-15 | |
| `stroke-dash` | 0-10 | dashed lines / borders |
| `border-radius` | 0-20 | large = pill; on connections rounds corners (ELK) |
| `shadow` | true/false | shapes only |
| `3d` | true/false | `rectangle`/`square` only |
| `multiple` | true/false | stacked copies; shapes only |
| `double-border` | true/false | rectangles and ovals |
| `font` | `mono` | only option |
| `font-size` | 8-100 | |
| `font-color` | color | tables/classes: header text only |
| `bold`, `italic`, `underline` | true/false | shape labels are bold by default; `bold: false` to see italic |
| `text-transform` | `uppercase`, `lowercase`, `title`, `none` | |
| `animated` | true/false | connections: moving dashes |
| `filled` | true/false | **arrowheads only** |

Root-level `style` (diagram background/frame): `fill`, `fill-pattern`, `stroke`,
`stroke-width`, `stroke-dash`, `double-border`.

```d2
a -> b: label {
  source-arrowhead: 1              # arrowhead label (keep short)
  target-arrowhead: * {
    shape: diamond                 # triangle (default) | arrow | diamond | circle | box | cross
    style.filled: true             # | cf-one | cf-one-required | cf-many | cf-many-required
  }
}
```

An arrowhead only renders where the connection has that endpoint (`->` has no source head).

## 5. Classes and vars

`classes` bundles attributes; apply with `class: name` or `class: [a; b]` (left to right,
later wins). Attributes set directly on the object override the class. Prefer classes over
ad-hoc styles so one meaning (external system, datastore, async edge) always looks the same.

```d2
classes: {
  external: { style: { stroke-dash: 3; fill: "#f5f5f5"; font-color: "#555" } }
  database: { shape: cylinder; style.fill: "#dbeafe" }
  async: { style: { stroke-dash: 4; animated: true }; target-arrowhead.shape: arrow }
}
stripe: Stripe { class: external }
orders_db: Orders DB { class: database }
api -> queue: publish { class: async }
(api -> queue)[0].class: async       # apply to an existing connection
```

`vars` defines values substituted with `${name}`; nest with dots; inner `vars` shadow
outer ones; single-quoted strings are not substituted; `...${map}` spreads a map/array.

```d2
vars: {
  env: prod
  colors: { primary: "#4baae5" }
  d2-config: {                       # file-level config, same names as CLI flags
    layout-engine: elk               # dagre | elk | tala
    theme-id: 0
    dark-theme-id: 200
    pad: 20
    sketch: false
    center: true
  }
}
api: ${env}-api { style.fill: ${colors.primary} }
note: 'literal ${env}'               # single quotes bypass substitution
```

## 6. sql_table (ER diagrams)

Each key is a column, its value the type, `constraint` a third column.
`primary_key`/`foreign_key`/`unique` render as `PK`/`FK`/`UNQ`; other strings render as
written. Foreign keys are connections between `table.column` keys (ELK/TALA route to the
exact row; dagre routes table to table). Tables nest in containers like any shape.

```d2
users: {
  shape: sql_table
  id: uuid { constraint: primary_key }
  email: varchar(255) { constraint: unique }
  org_id: uuid { constraint: foreign_key }
  created_at: timestamptz
  "label": text                      # quote column names that are D2 reserved words
}
orgs: {
  shape: sql_table
  id: uuid { constraint: [primary_key; unique] }   # several constraints as an array
  name: varchar(100)
}
users.org_id -> orgs.id: belongs to
```

## 7. UML class shape

Keys are fields (value = type) or methods (any key containing `(`; value = return type,
none = void). Visibility prefixes: none/`+` public, `-` private, `#` protected (write `\#`
so it is not parsed as a comment).

```d2
OrderService: {
  shape: class
  -repo: OrderRepository
  +cache: "map[string]Order"        # quote types containing [ ] or other special chars
  \#logger: Logger
  +Create(o Order): (id string, err error)
  +Cancel(id string)
}
OrderService -> OrderRepository: uses
PaidOrder -> Order: {               # inheritance: hollow triangle
  target-arrowhead.shape: triangle
  target-arrowhead.style.filled: false
}
Order -- LineItem: has { source-arrowhead: 1; target-arrowhead: 1..* }   # multiplicities
```

## 8. Sequence diagrams

Set `shape: sequence_diagram` on a container (or at the root of the file).

- **Order matters**: actors appear left to right in first-mention order, messages in source
  order. Declare actors first (`client; api; db`) to fix their order and shape them.
- **Shared scope**: `api` means the same actor everywhere inside the diagram, including in
  groups; anything referenced inside a group must already exist at the top level.
- Span (activation bar) = nested key on an actor (`svc.handle`); spans nest. Group
  (fragment) = container with connections inside but none to it. Note = nested object on an
  actor with no connections. Self-message = `a -> a`. Lifelines inherit the actor's
  `stroke`/`stroke-dash`. `direction` has no effect inside.

```d2
shape: sequence_diagram
client: Browser { shape: person }
api: API Gateway
svc: Order Service
db: Orders DB { shape: cylinder }

client -> api: POST /orders
api -> svc.handle: createOrder()
svc.handle -> db: INSERT order
db -> svc.handle: ok { style.stroke-dash: 3 }      # dashed reply
svc.handle -> svc.handle: emit event               # self-message
svc."Retries 3x with backoff"                      # note
svc.handle -> api: 201 Created
payment failed: {                                  # group
  api -> client: 402 Payment Required
}
api -> client: 201 Created
```

## 9. Grid diagrams

`grid-rows` and/or `grid-columns` on a container lay out its children in source order (the
keyword written first is the fill direction). Spacing: `grid-gap`, `vertical-gap`,
`horizontal-gap`; size cells with `width`/`height`; pad with invisible cells
(`style.opacity: 0`). Cells can be containers, grids or sequence diagrams.

```d2
services: {
  grid-columns: 3
  grid-gap: 20
  auth; orders; billing
  search; inventory; notifications
}
```

## 10. Layout engines and readability

| Engine | Choose when | Notes |
| --- | --- | --- |
| `dagre` (default) | small/medium flowcharts, trees | fast; curved multi-segment edges; no container-to-own-child edges; weaker container routing |
| `elk` | infra/architecture with nested containers, ER diagrams, anything over ~15 nodes | orthogonal routes, fewer crossings, native container-to-container routing, FK edges hit exact rows |
| `tala` | non-hierarchical architecture where symmetry matters | per-container `direction`, `near: <object>`, `top`/`left` pinning; some randomness; bundled from v0.9.0 |

Readability tips:

- One `direction` that matches the story: `right` for request flows and pipelines, `down`
  for layered architectures and hierarchies.
- Group by boundary (cloud account, VPC, cluster, bounded context, swimlane) with
  containers, at most 2-3 levels deep.
- Fewer edges: connect containers rather than every child; one labeled edge beats several
  unlabeled ones; edge labels of 1-3 words. Put detail in `tooltip` or a `|md` note.
- Encode meaning with classes: dashed = async/external, cylinder = store, `person` = user.
- Above ~30 nodes, split into one diagram per subsystem. Run `d2 fmt` and `d2 validate`.

## 11. Gotchas

- **Connect by key, not label.** With `be: Backend`, `Backend -> x` creates a new shape;
  write `be -> x`.
- **Hex colors need quotes** (`"#0f0"`): `#` starts a comment anywhere in a line, so `#`
  inside an unquoted label also truncates it (use `\#` or quotes).
- **Hyphens**: `a-shape` is one key; `a--shape` is a connection. Avoid keys starting or
  ending with `-`, `<`, `>`.
- **Redeclaring a key merges** attributes into the same object (no error); redeclaring a
  connection adds another edge; edit an existing one via `(a -> b)[0]`.
- **Reserved keywords cannot be plain keys**: `label`, `shape`, `icon`, `style`, `near`,
  `width`, `height`, `link`, `tooltip`, `constraint`, `direction`, `class`, `classes`,
  `vars`, `grid-rows`, `grid-columns`, `grid-gap`, `vertical-gap`, `horizontal-gap`,
  `source-arrowhead`, `target-arrowhead`, `top`, `left`, `layers`, `scenarios`, `steps`,
  and every style keyword. Quote them (`"label": text`) when they must be a column/field.
- Unquoted values cannot contain `:` `;` `{` `}` `|` `#`; quote such labels
  (`a -> b: "GET /x?y=1; retry"`). Parentheses, slashes, `?`, `=` and `,` are fine.
- **`near`** accepts only `top-left|top-center|top-right|center-left|center-right|
  bottom-left|bottom-center|bottom-right` (plus `outside-*`/`border-*` variants under
  `label.near`/`icon.near`). `near: <object>` is TALA-only, never an ancestor/descendant.
- **`direction` is global** in dagre and ELK; per-container direction is TALA-only.
- **Container -> its own child** edges do not work in dagre; use ELK/TALA.
- `style.filled` only on arrowheads; `3d` only rectangle/square; `double-border` only
  rectangles/ovals; `fill`, `shadow`, `multiple`, `fill-pattern` only on shapes;
  `width`/`height` on containers only in ELK/TALA.
- A `|md` block needs an explicit `shape:` to get a box around it.
- Remote icons are fetched at render time (the only network use); use local paths or omit
  icons offline. Increase `--timeout` for big diagrams.

## 12. Complete examples

### (a) Infrastructure overview

```d2
direction: right
vars: { d2-config: { layout-engine: elk; pad: 20 } }

classes: {
  external: { style: { stroke-dash: 3; fill: "#f3f4f6"; stroke: "#6b7280"; font-color: "#374151" } }
  database: { shape: cylinder; style.fill: "#dbeafe" }
  queue: { shape: queue; style.fill: "#fef3c7" }
  async: { style.stroke-dash: 4; target-arrowhead.shape: arrow }
}

users: Users { shape: person }

aws: AWS us-east-1 {
  style.fill: "#f9fafb"
  lb: Application Load Balancer
  eks: EKS Cluster {
    web: Web App { style.multiple: true }
    api: Orders API { style.multiple: true }
    worker: Billing Worker
  }
  data: Data tier {
    pg: PostgreSQL (RDS) { class: database }
    redis: ElastiCache Redis { class: database }
    sqs: orders-events { class: queue }
  }
  lb -> eks.web: HTTPS
  lb -> eks.api: HTTPS
  eks.web -> eks.api: REST
  eks.api -> data.pg: SQL
  eks.api -> data.redis: cache
  eks.api -> data.sqs: publish { class: async }
  data.sqs -> eks.worker: consume { class: async }
}

stripe: Stripe { class: external }
users -> aws.lb: HTTPS
aws.eks.worker -> stripe: charge
```

### (b) Business-process flowchart with swimlanes

```d2
direction: down

classes: {
  decision: { shape: diamond; style.fill: "#fef9c3" }
  terminal: { shape: oval; style.fill: "#dcfce7" }
  lane: { style: { fill: "#f8fafc"; stroke: "#cbd5e1"; stroke-dash: 2 } }
}

customer: Customer {
  class: lane
  start: Places order { class: terminal }
  pay: Enters payment
  done: Receives confirmation { class: terminal }
}
orders: Order Service {
  class: lane
  validate: Validate cart
  in_stock: In stock? { class: decision }
  reserve: Reserve inventory
  reject: Reject order { class: terminal }
}
billing: Billing Service {
  class: lane
  charge: Charge card
  ok: Charge ok? { class: decision }
}
fulfillment: Fulfillment {
  class: lane
  ship: Create shipment
}

customer.start -> orders.validate -> orders.in_stock
orders.in_stock -> orders.reject: no
orders.in_stock -> orders.reserve: yes
orders.reserve -> customer.pay -> billing.charge -> billing.ok
billing.ok -> orders.reject: no
billing.ok -> fulfillment.ship: yes
fulfillment.ship -> customer.done
```

### (c) Sequence diagram of a request flow

```d2
shape: sequence_diagram

client: Mobile App { shape: person }
api: API Gateway
svc: Order Service
db: Orders DB { shape: cylinder }
psp: Payment Provider { style.stroke-dash: 3 }

client -> api: "POST /orders {items, card}"     # quoted: { } would open a map
api -> api: authenticate JWT
api -> svc.create: createOrder(cmd)
svc.create -> db: "BEGIN; INSERT orders"        # quoted: ; would end the statement
db -> svc.create: order_id
svc.create -> psp: authorize(amount, card)
payment declined: {
  psp -> svc.create: 402 declined { style.stroke-dash: 3 }
  svc.create -> db: ROLLBACK
  svc.create -> api: PaymentDeclined
  api -> client: 402 Payment Required
}
psp -> svc.create: auth_id { style.stroke-dash: 3 }
svc.create -> db: "UPDATE orders SET status = paid; COMMIT"
svc."Publishes OrderPaid event asynchronously"
svc.create -> api: OrderCreated(order_id)
api -> client: "201 Created {order_id}"
```
